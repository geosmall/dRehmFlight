# tunes/ — validated dRehmFlight model tunes

One file per model: `<MODEL>_<board-target>.txt` (e.g. `AIR75_BEFH-G473.txt`,
`PAVO-PICO-II_<board>.txt`). Git history *is* the tune history — update a model's file in
place; don't date-stamp filenames. Only archive tunes built from a **clean** (non-`-dirty`)
commit.

Contents = the firmware's self-stamped `diff all`: a provenance header (build identity +
board) followed by every param as a paste-back `set name = value` line. `diff all` pins
absolute values, so a restore doesn't depend on a future firmware's defaults.

## Capturing a tune

After a successful flight test, with the board on USB (props off):

```
tools/save_tune.sh <MODEL>_<board-target> [port]
# e.g.
tools/save_tune.sh AIR75_BEFH-G473 /dev/ttyACM0
```

`save_tune.sh` gates on MSP identity, captures `diff all`, **refuses** to save if the
firmware's `fw_git` is `-dirty`, `nogit`, or `unknown` (a tune you can't rebuild is not a
backup), writes `tunes/<MODEL>_<board-target>.txt`, then commit it.

The firmware self-stamps automatically: `build_id.h` (git SHA + `-dirty` + commit time) is
generated by the core prebuild hook (`Arduino_Core_STM32/system/extras/prebuild.sh`) on
**every** compile — no flag needed — and reported via the CLI `version` and `diff`/`diff all`
headers and the boot banner. A dirty tree reports `<sha>-dirty`; a build made outside the git
repo reports `nogit`. Only a clean committed build yields a bare SHA that `save_tune.sh` accepts.

## Restoring a tune

Enter the CLI (`#`), paste the whole file (the `#` header lines are treated as comments),
then `save`. Verify with `diff all` against the saved file.

## File format

```
# dRehmFlight diff all - fw_git: <sha>  branch: <branch>  built: <utc>
# board: <MSP board name> / DRHM <fc-version>
set Kp_roll_angle = 0.200000
set thr_mid = 0.400000
set yaw_motors_reversed = 1.000000
set AccErrorX = 0.035036
...
```

> Legacy note: tunes captured before the provenance firmware (`AIR75_BEFH-G473.txt` as first
> archived) use a hand-prepended header over a raw `dump`, with `fw_git` *asserted* rather
> than self-reported. Re-capture with `save_tune.sh` on the next validated build to upgrade
> them to a self-stamped `diff all`.
