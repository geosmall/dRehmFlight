# src/xcos2c — generated X-quad mixer (do not hand-edit)

Machine-generated flight mixer, spliced into `controlMixer()` in place of the
hand-written mixing expressions (xcos2c Phase 4, MIXER_SPEC). The model is the
Xcos-authored unclamped topology-B X-quad mixer: inputs
`thro_des/roll_pid/pitch_pid/yaw_pid`, outputs `m1..m4` (dRehmFlight motor
order FL, FR, BR, BL), no saturation — clamping stays downstream in
`scaleCommands()`.

| File | Origin |
|---|---|
| `mixer.{h,c}`, `mixer.map.json` | generated by `xcos2c` from `xcos2c/tests/golden/xquad_mixer_flight/model_ir.json` |
| `xcb_summation.{h,c}` | copied from `xcos2c/runtime/blocks/` (the only block this model uses) |
| `xcos2c_types.h` | copied from `xcos2c/runtime/` (`real_t` = `float` here, matching the sketch) |

## Regenerate

From the `xcos2c` repo root:

```bash
python3 generator/xcos2c.py tests/golden/xquad_mixer_flight/model_ir.json \
  -o ../dRehmFlight/Versions/dRehmFlight_STM32_BETA_1.3/src/xcos2c \
  --name mixer --dt 0.0005
cp runtime/xcos2c_types.h runtime/blocks/xcb_summation.{h,c} \
  ../dRehmFlight/Versions/dRehmFlight_STM32_BETA_1.3/src/xcos2c/
```

Generator output is deterministic — a regeneration diff means the model or
the generator moved, and it is reviewed like code.

## Numerical equivalence

The generated mixer is **bit-identical** to the hand-written expressions it
replaced: the model's SUMMATION blocks accumulate in the C's left-to-right
operand order (thro, pitch, roll, yaw), verified over 400k stimulus points by
the xcos2c `make check` equivalence gate (`tests/equiv/`) and by L2/L3 golden
comparisons. This particular model contains **no multiplies**, so its
arithmetic is immune to `-ffp-contract` FMA fusion and the result holds at the
core's default build flags. Future generated modules with gains/products WILL
need the xcos2c conformance flags (`-O2 -ffp-contract=off`) plumbed into the
sketch build to keep bit-equality (CODEGEN_SPEC §3).
